# Contributing

Thanks for taking the time. These are the defaults for every Aryabhatta Labs repository. A repository's own `CONTRIBUTING.md`, if it has one, takes precedence.

## Reporting a problem

Open an issue on the repository it concerns. The most useful reports include:

- what you ran, and what you expected to happen;
- what happened instead, with the full error text;
- your versions (the tool, the language runtime, the operating system).

Issues are public. Leave out API keys, tokens, customer data and anything else you would not post on the open web.

For a security problem, don't open an issue. Follow [SECURITY.md](SECURITY.md).

## Suggesting a change

Open an issue before a large pull request, so we can agree on the approach before you spend time on it. Small fixes (a typo, a broken link, an obvious bug) can go straight to a pull request.

## Pull requests

- Keep each pull request to one change.
- Add or update tests for any change in behaviour, and run the test suite before you push.
- Say in the description what changed, why, and how you checked it.
- By contributing to an open-source repository here, you agree that your contribution is released under that repository's licence.

## Closed-source tools

Some tools published here are free to use with the source closed (Taught, during its beta). Their repositories hold documentation, releases and issues only. Bug reports and feedback are welcome there; code contributions are not possible yet.

## Response times

This is a small lab. We read everything, and reply when we can.
